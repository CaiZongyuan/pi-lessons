# 术语表



本书对各个术语的用法，以及定义该术语的章节。



|术语|含义|参见|
|---|---|---|
|Agent（智能体）|对话运行时使用的配置：模型、思考级别、扩展、工具、指令、`cwd`|7\.2（原书第106页）|
|Background（后台）|由对话拥有，但不参与空闲等待、对话中止和级联的任务|5\.5（原书第76页）|
|Base（基值）|存储的完整文档值；之后的变更作为增量叠加在它之上|4\.3（原书第56页）|
|Blocked（阻塞）|没有任何已注册定义能够接手的活动任务；该状态由推导得出，从不存储|5\.4（原书第73页）|
|Boundary（边界）|轮次之间收件箱放入条目的位置：`postTools` 或 `final`|6\.1（原书第84页）|
|Checkpoint（检查点）|任务恢复所依据的完整持久化状态；其中的 `phase` 指定处理器|5\.1（原书第63页）|
|Chord|将文档表示为值和操作的复制状态库|8\.1（原书第125页）|
|Commit（提交）|在变更串行队列上对记录和文档进行的一次原子写入|2\.2（原书第29页）|
|Completing（正在完成）|结局已经确定，但因拥有的工作仍活动而被暂缓结束的任务|5\.5（原书第76页）|
|Context（上下文）|从对话记录中推导出来、供下一次模型请求使用的消息|3\.2（原书第40页）|
|Conversation（对话）|一份对话记录的作用域；可以从另一段对话分叉，也可以由任务拥有|3\.3（原书第43页）|
|Definition（定义）|描述文档、文档族、条目种类或任务的类型化标记|4\.1（原书第50页）|
|Document（文档）|以 Chord 操作和基值存储的类型化可变 JSON 状态|4\.1（原书第50页）|
|Effect sandwich（副作用三明治）|提交意图，执行副作用，提交结果|5\.3（原书第70页）|
|Entry（条目）|不可变的对话记录条目，包含种类、模型消息和数据|3\.1（原书第37页）|
|Extension（扩展）|一组有名称的工具、提示词区段、钩子、包装器和任务|7\.1（原书第103页）|
|Fork（分叉）|继承父对话截至 `parent.at` 的历史的对话|3\.3（原书第43页）|
|Generation（生成）|一次模型请求及对其结果的分类，由 `pi.generation` 运行|6\.3（原书第91页）|
|Harness|一份已打开的存储，加上在其上运行智能体的机制|1\.2（原书第13页）|
|Head（头指针）|指定活动上下文第一个条目的条目字段|3\.4（原书第46页）|
|Hook（钩子）|内置任务调用的扩展处理器，例如 `beforeTool`|7\.3（原书第109页）|
|Inbox（收件箱）|保存排队提交请求的 `pi.inbox` 文档|6\.1（原书第84页）|
|Invocation（调用）|任务某个阶段或中止处理器在内存中的一次运行|5\.4（原书第73页）|
|Memo（备忘）|存储在活动任务上的小值，遵循首次写入胜出原则|5\.2（原书第67页）|
|Mutation line（变更串行队列）|Session 中唯一的提交串行化路径|2\.2（原书第29页）|
|Orphaned（孤儿状态）|在不执行任何任务代码的情况下，通过中止完成结算的阻塞任务|5\.6（原书第80页）|
|Outcome（结局）|任务的终态结果：`completed, failed, aborted, orphaned, faulted`|5\.1（原书第63页）|
|Owner, owned work（所有者、拥有的工作）|创建任务或对话的那段对话或任务；拥有的工作会拖住所有者，并随所有者一起中止|5\.5（原书第76页）|
|Phase（阶段）|任务中带名称的步骤，每个阶段对应一个处理器|5\.2（原书第67页）|
|Registry（注册表）|进程本地、不会存储的已安装扩展集合|7\.1（原书第103页）|
|Replay（重放）|工具对中断调用是否可以重新运行的声明：`safe` 或 `unsafe`|6\.4（原书第94页）|
|Run（运行）|从获准进入的输入到最终回答之间的全部轮次；期间对话处于繁忙状态|6\.2（原书第88页）|
|Section（提示词区段）|系统提示词中带名称的部分，每次请求前渲染|7\.5（原书第115页）|
|Session|一条变更串行队列及其记录和文档的所有者|1\.3（原书第16页）|
|Settings（设置）|Harness 范围内的运行策略，每次使用时读取，从不存储|7\.2（原书第106页）|
|Storage（存储）|原子地持久化提交的后端：Memory、SQLite、JSONL|9\.1（原书第141页）|
|Submission（提交请求）|获准进入的用户输入或条目写入，宿主可以等待它完成|6\.1（原书第84页）|
|Task（任务）|附属于一段对话的持久化状态机|5\.1（原书第63页）|
|Tool call（工具调用）|模型提出的一次运行工具的请求，由 `pi.tool` 任务执行|6\.4（原书第94页）|
|Turn（轮次）|一次助手响应，以及它发起的工具调用|1\.3（原书第16页）|
|View（视图）|对话的结构化挂载：记录、活动条目、内置文档|8\.2（原书第129页）|
|Watch（监听）|串行化的精确帧观察，最多包含 100 个待处理帧|8\.2（原书第129页）|
|Wrap（包装器）|扩展提供的工具或提示词区段装饰器，按名称指定目标|7\.4（原书第112页）|



来源：spec §1（术语）；README §Concepts；`src/types.ts`；`src/harness/types.ts`；`AUTHORING.md` 的规范术语。
