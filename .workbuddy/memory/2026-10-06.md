### 流水线（`work/` 下四个脚本，按序执行）

1. `extract.py <首页> <末页> <输出目录>` — PyMuPDF 抽文本块 + 裁图
   - PDF 由 Chrome + Paged.js 生成：**所有字体都是 Type3 子集、书签页码全是 1、零张位图**（图表全是矢量）。因此结构只能靠几何信息（字号/颜色/坐标）还原，不能依赖 TOC。
   - 判角色：字号 ≥30 = 部分标题，≥19 = 章标题，11–13 = 小节标题，10.2–10.6 = 导语，≤8.7 = 图注小字。
   - 裁图：用「FIG. n.n」图注块当上锚，取**该位置最大面积的矩形 drawing**当图框（每张图都画在带边框的面板里），下边界 = 图框底边。200 DPI。像素级对齐。

2. `normalize.py <输出目录>` — 逐行块重组为语义 IR
   - PyMuPDF **一行一个 block**，需按垂直间距重新拼成段落。正文左边距 57.6，列表项 71.6，据此区分段落与列表。
   - `block_text()` 必须用 `\n` 连接各行、而行内 span 直接相连——否则 "every visible" + "step" 会粘成 "visiblestep"。

3. subagent 翻译 — 写 `zh` / `zh_caption` 字段，`code` 节点禁止改动
4. `render.py <IR目录> <输出html>` — 出 HTML；`style.css` 为公用样式

### 踩过的坑

- **SVG 方案已放弃**：PyMuPDF 能导出带真实 `<text>` 的 SVG（`text_as_path=0` + `set_cropbox`），但每个词一个 text 节点且带逐字 x 坐标，Type3 字体不存在导致回退字体重排、跨列文字重叠。改用 200 DPI PNG 裁图，保真且视觉无损。
- **代码高亮不能用多次正则替换**：会产出 `<span class="k"><span class="k">`。改为单次左到右 token 扫描，标签必然配对。
- **图注去重**：同一段图注会以「截断版」（figure.caption）和「完整版」（紧随的 small 节点）各出现一次。用最长公共子串覆盖率判断（≥0.6 即视为重复），保留完整版。
- **图注会混进代码块末尾**：小字号散文行被 `is_codeish` 误判。`split_caption_lines()` 按「括号配平 + 字母占比 > 0.82 + ≥7 词」识别并拆出。
